# M1 迁移实现说明

## 本体与参数

模型来自用户提供的 `ZG_M1_A0_V1_0.rar`。原始 URDF 有 33 个 link、16 个非固定关节，质量合计 42.338 kg，轮子碰撞圆柱半径 0.0975 m。处理脚本逐项保留原质量、质心、惯量和运动关节轴；测试验证这些属性与原始文件完全一致。

训练模型只做以下处理：四个 FOOT 从超宽限位的 revolute 改成 continuous，保留 effort/velocity；修复相对 mesh 路径；移除 BASE_LINK 内 12 个传感器小 mesh 碰撞体，保留 11 个机身基础碰撞体及腿、轮碰撞体。完整原始 URDF 和 meshes 一并保留，manifest 记录输入和输出 SHA-256。简化后的碰撞体不用于传感器精细碰撞评估。

腿部最大扭矩/速度仍为 M1 URDF 的 180 N·m / 16.75 rad/s，轮子为 28.68 N·m / 110 rad/s。这是模型中声明的限制，未验证是否为连续额定值。借用 A2 的内容仅为腿部 kp/kd，来源固定到 commit；不复制 A2 的惯量、armature 或 effort_limit。

## 命名与控制契约

| M1 前缀 | 物理腿 | SDK leg slot |
|---|---|---:|
| FAR | 前右 FR | 0 |
| FBL | 前左 FL | 1 |
| RAR | 后右 RR | 2 |
| RBL | 后左 RL | 3 |

策略动作前 12 维依次为 FAR、FBL、RAR、RBL，每腿 ABAD/HIP/KNEE；后 4 维为同腿顺序的 FOOT。SDK 则按每条腿 abad/hip/knee/foot 交错布局，不能直接复制策略向量。M1 ABAD 对应 A2 hip，M1 HIP 对应 A2 thigh，M1 KNEE 对应 A2 calf；参数按名字选取，不依赖 PhysX 或 URDF 的自然排序。

前腿站姿为 `[0, 0.65, -1.30]` rad，后腿为 `[0, -0.65, 1.30]` rad；轮角为 0 但不参与位置观测。这个站姿在 M1 URDF 坐标中定义，是经 CPU 检查的仿真初始姿态，不是硬件零位。初始机身 z=0.54 m；无负载形变的四轮接地高度约 0.5272 m。

腿位置目标为 `q_default + action * scale`，ABAD scale=0.15、HIP/KNEE scale=0.35 rad；轮速度目标为 `action*5` rad/s，参考 robot_lab B2W 的动作缩放。RSL wrapper 将原始动作截到 ±3。腿部的最大目标偏移为 ±0.45 / ±1.05 / ±1.05 rad，轮速度目标范围为 ±15 rad/s。四轮 kp=0、kd=1，按用户最新要求参考 B2W；轮扭矩为 `kd*(dq_target-dq)` 并按 M1 扭矩限值裁剪。使用标准 JointVelocityAction，仅发送轮速度目标，无位置轨迹或位置反馈。轮子绝对角度不进入策略观测；真实部署必须复现动作顺序、缩放和速度反馈控制律。

策略周期 20 ms，物理步长 1 ms。执行器为显式延迟 PD，每个仿真环境在重置时抽样 0–20 个物理步的延迟。此范围、地面摩擦和观测噪声是训练假设，不是 A2/A2W 实测 sysid。该模型包含扭矩限幅，不包含已辨识的扭矩—转速曲线。固定 rotor link 的 CAD 惯量保留，另外的反射电机惯量暂设为 0。

## 观测、奖励与地形

actor 使用 53 维单帧本体感知：角速度 3、重力投影 3、速度命令 3、12 个腿相对位置、16 个关节速度、16 个上一动作。角速度 scale=0.25，关节速度 scale=0.05，其他项为 1。基座线速度不输入 actor；轮绝对角度不输入 actor 或 critic。critic 增加 3 维基座线速度和 187 维高度扫描，共 243 维。

平地任务保留 critic 高度扫描，以保持网络维度并支持继续训练。critic 的地形信息仅在仿真训练时使用；没有实现在线高度图输入、教师学生蒸馏或速度估计器。

复用 robot_lab B2W 的速度跟踪、能耗、动作平滑、关节限位和接触奖励。降低过强的姿态偏离惩罚，关闭写死 B2W 名称的对称与强制步态奖励，保留 wheel foot_slide 权重为 0，避免把正常滚动惩罚成点足滑动。未添加未经验证的轮接触滑移模型。

与上游 B2W 的任意朝向重置不同，本任务从站立附近重置。躯干触地或倾角超过 1 rad 终止；不训练自起身。混合任务为 10 行地形难度、20 列地形类型，初始地形等级不高于 1。质量随机化是以 M1 为中心的 ±15%，与 A2/A2W 的质量无关；质心 ±2 cm，PD 增益以所配置 kp/kd 为中心做 0.8–1.2 倍随机化。

## 真机对接边界

附件 `lowlevel.h` 声明了关节 `p_des/v_des/kp/kd/t_ff` 和 IMU 四元数 `w,x,y,z`。SDK 示例的前进轮方向为 `+,-,+,-`；M1 URDF 四轮在所选站姿下的正轴都为机身 +Y。必须独立核对符号和零位，不能把本工程的 URDF 关节坐标直接发给电机。

真实接口需要逐关节确认 `q_sdk = sign*q_urdf + offset`，速度和力矩也随 sign 变换，并验证 IMU 安装方向、角速度坐标系、状态时效与遥控接管。现有资料中的站姿示例不是经过验证的这份映射。本工程没有连接机器人或执行附件中的部署脚本，也没有生成会自动写共享内存的推理程序。

在 GPU 训练结果和坐标映射具备后，再开展 Sim2Sim 和真机部署。CPU 模型检查不代替这些步骤。
